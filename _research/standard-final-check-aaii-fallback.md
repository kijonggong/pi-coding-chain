# 마지막 수정 확인 — aaii-router fallback

판정 기준은 `docs/engineering-standard.md`이며 Iron Laws와 MATLAB은 제외했다. 검토 범위는 처분 기록의 「독립 재리뷰 처분」에 있는 NF1·NF2·NF3·NF4·NF6의 마지막 수정과 그 수정으로 생긴 위반 여부다. 소스·시험·기존 문서는 편집하지 않았으며 커밋하지 않았다. 작성한 저장소 파일은 이 보고서 하나다.

## 1. 항목별 재판정

## 2. 새 위반 여부 — 정본 3절과 2.9

**마지막 수정에서 새로 생긴 수정 필수 위반은 발견하지 못했다.**

3절의 세 질문을 적용한 결과:

1. **기존 책임 옆에 같은 일을 하는 길을 더했는가: 아니오.** NF1은 중복 시험을 삭제했고 NF2는 유효한 입력으로 정리했다. NF3은 기존 상수를 직접 소비하며 NF4는 설명 범위를 바로잡았다. NF6은 기존 저장 경계의 Promise를 직접 기다린다.
2. **대체된 것이 남았는가: 아니오.** candidates의 전진 시험과 import, 목록 내부의 중복 입력, 해당 표시의 `99`, 과장된 미리보기 설명, 저장 실패/재시도 시험의 `setTimeout(10)`이 남지 않았다.
3. **다음 담당이 덧댄 경로를 원래 설계로 오인할 수 있는가: 새 위험 없음.** NF6의 async 함수는 실패 가능한 외부 저장 작업을 표현하는 대역 자체다. 호출을 전달하기만 하는 새 helper나 제품 코드의 시험 전용 hook이 아니며, 실제 편집기 `handleInput`·`onSave(...).then`·상태 갱신·렌더·완료 콜백을 통과한다. 처분 기록 `:102`–`:107`은 이번에 뺀 것과 바꾼 이유를 명시한다.

2.9의 다섯 질문도 다음과 같이 확인했다.

| 질문 | 확인 결과 |
|---|---|
| 고장 주입 경계와 관측이 분명한가 | NF6은 외부 저장 콜백에서 `EACCES`를 거부시키고 오류 표시·초안 유지·미종료·복구 후 종료를 본다. pending 시험 `fallback-tui.test.ts:297`은 별도로 미완료 저장 중 중복 호출과 키 입력 차단을 본다. 실패 시험의 제목에 있는 중복 저장 방지는 이 pending 시험이 실제로 보호한다. |
| 실제 생산자·소비자를 잇는가 | NF2는 실제 편집기 설정 생산자와 초기화 소비자를 연결한다. NF6은 실제 컴포넌트가 받는 동일 Promise를 시험이 관측한다. 디스크 쓰기 자체의 EACCES를 재현하는 시험이라고 과장하지 않는다. |
| 기대값이 구현에서 복사되지 않았는가 | NF1의 보존 계약은 `a/alpha`, `c/gamma`, `d/delta`, `undefined` 같은 독립 기대값이다. NF6의 오류 문자열·핀 목록·미종료/종료 기대도 literal이다. NF2의 중첩 결과 비교는 특정 정렬 알고리즘의 사본이 아니라 왕복 안정성 계약이다. 기존 제품 상수 기반 시험은 아래 부채로 남는다. |
| 대역이 결함을 대신 처리하거나 경로를 우회하는가 | NF6 대역은 성공/실패만 반환하며 편집기 상태를 수정하지 않는다. 오류 처리는 제품 `fallback-tui.ts:181`–`:190`, 성공 종료는 `:177`–`:180`이 한다. 제품이 오류 표시나 saving 해제를 누락하면 오류 표시 또는 재시도 관측이 실패한다. SDK 키 파싱은 기존 외부 대역 경계다. |
| 다른 시험과 같은 경계를 불필요하게 반복하는가 | NF1의 중복을 제거했다. NF2의 왕복 안정성, NF6의 거부 후 재시도, pending 시험의 미완료 중 입력 차단은 서로 다른 상태 전이 계약이다. 저장 시도 횟수는 외부 저장 부작용의 중복 방지/재시도 계약이며 렌더 내부 호출 횟수 고정과 다르다. |

NF6 동기화는 시간이 아니라 Promise의 정착에 의존한다. 제품은 `fallback-tui.ts:176`에서 동일 Promise에 성공/실패 핸들러를 등록한 뒤 `handleInput`을 반환한다. 시험은 그 뒤 `assert.rejects(save, ...)` 또는 `await save`를 등록하므로 제품의 해당 핸들러가 먼저 실행된다. 제품 핸들러의 상태 갱신과 완료 호출은 그 핸들러 안에서 동기적으로 끝난다. 따라서 임의의 microtask 횟수나 밀리초 지연을 추측하는 대기도 아니다. 향후 제품이 핸들러 안에 별도의 비동기 후속 작업을 추가한다면 그때 완료 경계를 다시 검토해야 한다.

이번 확인은 읽기 전용이므로 새 mutation 실행은 하지 않았다. 처분 기록의 앞선 mutation 결과를 새 실행으로 간주하지 않는다. 마지막 변경은 중복/불가능 입력/시간 대기 제거와 상수·문구 정정이며, 위 내용은 검출 경로를 정적으로 대조한 결과다.

## 3. 남은 부채 기록의 정직성

**부채가 해결됐다고 숨기거나 현재 실패를 통과로 바꾼 기록은 없다.** 처분 기록 `:96`–`:98`은 “세션 이전 미커밋 작업”과 “같은 변경 집합에서 지금 고칠 대상”을 구분하고 F4/F7을 수정으로 재분류했다. 아래 항목을 마지막 수정의 새 결함으로 보지는 않는다.

| 항목 | 현재 근거 | 기록 판정 |
|---|---|---|
| NF5, mut-2 | `settings.test.ts:39`–`:40`의 `DEFAULT_SETTINGS`/`DEFAULT_COOLDOWN_MS`, `:274`·`:295`의 `SETTINGS.map`, `cooldown.test.ts:78`–`:83`의 제품 기본 상수 기반 기대가 남아 있다. | **실재하는 부채를 솔직하게 남김.** 처분 `:106`과 기존 부채 목록 `:58`에 기대값 출처 문제와 별도 정리 방침이 있다. 다만 “기본값·체인 개수 시험”이라는 요약은 NF5 전체보다 좁다. 자동완성/로드 applied 키의 제품 목록 기반 기대도 남아 있음을 이 보고서에 보충한다. 특히 해당 목록에는 체인 키도 들어가므로 “핀·제외와 무관”을 NF5의 모든 단정에 문자 그대로 적용할 수는 없다. 연결의 정합성 검사와 독립적인 공개 키 목록 검증은 구별해야 한다. 이 표현의 한계가 마지막 수정의 미해결 결함을 숨기는 것은 아니다. |
| mut-3 | `extensions/coding-fallback/chain.test.ts:293`–`:296`의 `CHAINS.length === 2` 및 alias 구성 단정이 그대로 있다. | **정직한 부채 기록.** 처분 `:106`에서 해결로 분류하지 않았다. 생성 결과 중심 검증으로 바꿀 후속 정리 대상이다. |
| NF7 | `fallback-tui.ts:78`–`:91`의 스타일 적용 전 span 폭 자르기와 `fallback-editor.ts:147`–`:158`의 순수 미리보기 폭 자르기가 남아 있다. | **정직한 부채 기록.** 처분 `:108`은 소비자가 다름과 검출력 보존을 이유로 이관했다고 적으며, 중복이 사라졌다고 주장하지 않는다. `fallback-tui.test.ts:284`와 `fallback-editor.test.ts:140`이 각각 실제 폭 계약을 확인한다. |
| index 상태 줄 catches | `index.ts:330`–`:339`와 `:723`–`:727`은 상태 UI 오류를 계속 무시한다. | **부채 내용은 정직함.** 처분 `:88`–`:90`은 오류 무시를 명시하며 2.7 재검토 대상으로 남긴다. 첫 위치는 현재 `:337`, 두 번째는 `:725`로 이동했다. 다만 “이번 세션 이전 코드”라는 시간적 출처는 현재 HEAD와의 diff만으로 입증할 수 없다. HEAD에는 이 상태 줄 코드가 없고 시작 시점의 `M` 표시는 개별 줄의 선재를 증명하지 않는다. 제공된 세션 기록의 주장으로만 취급하며 독립 확인 사실로 올리지 않는다. 이번 NF3 상수 수정이 이 catch를 추가하거나 넓히지는 않았다. |

부채 이관은 정본 위반의 해소를 뜻하지 않는다. 이번 제한 범위에서 부채를 다시 구현하거나 삭제할 권한은 없고, 새 수정의 문제를 범위 밖이라는 말로 덮은 경우도 발견하지 못했다. 원래 처분표·부채 목록은 차수별 기록이므로 F4/F7의 과거 부채 표기는 최신 `:98`·`:102`·`:104`의 수정 처분으로 읽어야 한다.

## 4. 시험 결과와 판정 범위

실행 명령:

```text
node --test extensions/aaii-router/*.test.ts extensions/coding-fallback/*.test.ts
```

결과: **tests 190 / pass 190 / fail 0 / cancelled 0 / skipped 0 / todo 0**, exit 0, duration 1144.4199 ms. 출력상 aaii-router는 89건, coding-fallback은 101건이다. 앞선 재리뷰의 191건에서 NF1 중복 시험 1건이 삭제된 수와 일치한다. Node의 기존 `MODULE_TYPELESS_PACKAGE_JSON` 경고는 있었고 실패나 skip은 없었다.

소스 import와 실제 로직을 쓰는 대역 통합은 이 실행으로 확인했다. 실제 Pi 터미널 세션에서 저장·라우팅·공급자 송신이 끝까지 동작하는 실물 증거는 이번에 만들지 않았다. `README.md:343`–`:352`도 SDK 프로토콜 파싱 및 실제 세션 경로의 시험 한계를 적는다. 처분 `:109`의 실제 SDK k/K 확인은 앞선 실행의 기록이며 이번에 재현한 증거가 아니다. 따라서 아래 ship은 **마지막 수정 라운드의 코드 검토상 추가 수정 없이 수락 가능**하다는 뜻이며, 실물 증거/실물 준비 완료를 새로 인증하는 뜻은 아니다.
